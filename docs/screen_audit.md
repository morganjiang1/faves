# Faves screen audit

Every screen was screenshotted and compared next to the reference it copies, at the same scale, and the differences were fixed or are listed below with the reason. The references are named in `docs/design_references.md` (catalog with measured values) and `docs/design_system.md` (component map), and each screen file names its reference in a header comment.

How the checks were made:

- **Web, phone size.** Headless Chrome has a minimum window width, so each page renders inside a 390 x 844 pt iframe on a wrapper page and is captured at 3x: `node scripts/shot.mjs <name> "<path>" [--click <testID>] [--fill <testID>=<text>] [--scroll <px>]` writes `docs/screens/<name>.png`.
- **Side by side.** `python3 scripts/side_by_side.py <name> <reference image> docs/screens/<name>.png [--crop x0,y0,x1,y1]` writes `docs/screens/pairs/<name>.png` with the reference on the left and Faves on the right at the same height.
- **iPhone.** The app also ran in Expo Go 58 on an iPhone 17 Pro simulator (iOS 26.5); captures are in `docs/screens/ios/`.
- Screenshots and pairs stay on the machine that made them (`docs/screens/` is not committed, like `references/`, because the pairs contain other apps' screenshots). Run the commands above to regenerate them.
- Console: every route was opened on the production web build with no console errors or warnings from Faves (the only messages come from inside TikTok's embedded player frame).
